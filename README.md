# สมุดบันทึกงาน

## โหมดออฟไลน์และการซิงก์

เมื่อตั้ง Supabase แล้ว บัญชีสมัคร/ล็อกอินผ่าน Supabase Auth และข้อมูลโปรไฟล์ งาน และตารางที่เคยโหลดจะถูกเก็บสำเนาไว้ใน IndexedDB ของเบราว์เซอร์ อุปกรณ์นั้นจึงยังเปิดข้อมูลเดิมและเพิ่ม/แก้ไข/ลบงานหรือตารางส่วนตัวได้โดยไม่ต่อเน็ต รายการที่แก้จะเข้าคิวและส่งขึ้น Supabase เมื่อออนไลน์อีกครั้ง (ต้องมีเซสชัน Supabase ที่ยังใช้ได้; หากหมดอายุให้เชื่อมต่อแล้วล็อกอินออนไลน์เพื่อซิงก์)

การล็อกอินออฟไลน์ต้องเคยล็อกอินออนไลน์บนเบราว์เซอร์/อุปกรณ์นั้นมาก่อน ระบบเก็บตัวตรวจรหัสผ่านแบบ PBKDF2 ในเครื่อง ไม่เก็บรหัสผ่านอ่านข้อความได้ ข้อมูลออฟไลน์ไม่ซิงก์ข้ามอุปกรณ์จนกว่าจะกลับมาออนไลน์และซิงก์สำเร็จ GitHub Pages ต้องเปิดผ่าน HTTPS และ service worker จะเริ่มแคชเว็บหลังเข้าครั้งแรกขณะออนไลน์; ควรเปิดเว็บออนไลน์หนึ่งครั้งก่อนใช้ออฟไลน์

เมื่อ `supabase-config.js` ยังมีค่า placeholder ระบบจะอยู่ในโหมดออฟไลน์ล้วน ใช้บัญชีหนึ่งบัญชีต่อเบราว์เซอร์และข้อมูลใน IndexedDB เท่านั้น; ยังไม่ใช่ฐานข้อมูลกลางและไม่ซิงก์ข้ามอุปกรณ์

1. เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน `python -m http.server 8000`
2. เปิด `http://localhost:8000`
3. สมัครด้วยชื่อจริง รหัสนักเรียน 5 หลัก ชั้น/ห้อง (เลขที่ในห้องไม่บังคับ) อีเมล และรหัสผ่านอย่างน้อย 8 ตัวอักษร อีเมลในโหมดออฟไลน์ยังส่งลิงก์กู้รหัสไม่ได้
4. ครั้งถัดไปเลือก “มีบัญชีแล้ว? เข้าสู่ระบบ” แล้วใช้รหัสนักเรียนกับรหัสผ่านเดิม
5. กด “เปิดแจ้งเตือน” แล้วอนุญาตจากหน้าต่างเบราว์เซอร์; ระบบจะแสดงการแจ้งเตือนทดสอบ และเตือนงานที่ถึงกำหนดขณะเปิดเว็บ (ขณะเปิดหน้าเว็บอยู่)
6. ใน “ข้อมูลนักเรียน” ต้องยืนยันรหัสผ่านปัจจุบันก่อนแก้ชื่อ รหัสนักเรียน ชั้น/ห้อง และเลขที่; รูปโปรไฟล์เปลี่ยนและบันทึกได้โดยไม่ต้องยืนยัน

## เปิดใช้ฐานข้อมูลและบัญชีจริงบน Supabase

1. สร้างโปรเจกต์ที่ [Supabase](https://supabase.com) และเก็บ Project URL กับ Publishable key ไว้
2. เปิด SQL Editor ของโปรเจกต์ แล้วรันไฟล์ `supabase-schema.sql` ทั้งไฟล์ เพื่อสร้างตาราง, RLS, trigger สร้างโปรไฟล์ และ bucket สำหรับเก็บโลโก้ผู้ใช้ภายนอก
3. เปิด Authentication > Providers > Email และตั้งค่าการยืนยันอีเมลตามนโยบายที่ต้องการ
4. ใส่ Project URL กับ Publishable/anon key ลงใน `supabase-config.js` แทนข้อความ `YOUR_...`
5. เปิดเว็บผ่าน `localhost` หรือ deploy ไฟล์เว็บไซต์ขึ้น HTTPS hosting เช่น Netlify, Vercel หรือ GitHub Pages
6. บัญชีนักเรียนใช้ชื่อจริง รหัสนักเรียน ชั้น/ห้อง อีเมล และรหัสผ่าน ส่วนบัญชีคนภายนอกเลือก **สำหรับคนภายนอก** เพื่อกรอกชื่อ ระดับชั้น ปีการศึกษา อีเมล และรหัสผ่าน พร้อมเพิ่มโลโก้ส่วนตัวได้ (ไม่บังคับ). ตารางของบัญชีภายนอกเป็นตารางส่วนตัวตามเจ้าของบัญชี
7. เมื่อยืนยันอีเมลแล้ว ครั้งต่อไปบนอุปกรณ์เดิมใช้รหัสนักเรียนกับรหัสผ่านได้ (อุปกรณ์ใหม่ให้กรอกอีเมลที่สมัครในช่องบัญชี) บัญชีภายนอกใช้ email กับรหัสผ่าน หากลืมรหัสผ่านให้กด “ลืมรหัสผ่าน?” เพื่อรับลิงก์ตั้งรหัสใหม่ทางอีเมล



หลังตั้งค่า URL/key และรัน schema แล้ว แอปใช้ Supabase Auth สำหรับบัญชี และ PostgreSQL ตาราง `profiles`/`assignments` สำหรับโปรไฟล์กับงาน แต่ละบัญชีอ่านและแก้ไขข้อมูลของตนผ่าน RLS ตารางเรียนของคนภายนอกเก็บเป็นตารางส่วนตัวตามเจ้าของบัญชี โลโก้ส่วนตัวเก็บใน Supabase Storage bucket `user-brand-logos` และเปิดอ่านผ่าน URL สาธารณะ ส่วนรูปโปรไฟล์เปลี่ยนได้โดยไม่ต้องยืนยันรหัสผ่าน

**ห้ามใส่ `service_role` key ในเว็บไซต์** ใช้เฉพาะ Publishable/anon key และปล่อย RLS เปิดอยู่เสมอ รหัสนักเรียนที่ผู้สมัครกรอกยังไม่ถือเป็นการยืนยันตัวตนจากโรงเรียน หากต้องตรวจสิทธิ์นักเรียนจริง ต้องเพิ่มขั้นตอนยืนยันผ่านอีเมล/ระบบของโรงเรียนก่อนเปิดสาธารณะ

ก่อนใช้ schema ที่มี class_code ให้รันไฟล์ supabase-schema.sql ฉบับล่าสุดอีกครั้งใน SQL Editor เพื่อเพิ่มชั้น/ห้องให้โปรไฟล์. การกู้รหัสผ่านใช้ลิงก์อีเมล Supabase (ไม่ใช่รหัส OTP) ดังนั้นต้องกำหนด Site URL และ Redirect URL ของเว็บไซต์ใน Supabase Authentication > URL Configuration และทดสอบจากอีเมลจริง. การรันในแชตนี้ยังใช้ฐานข้อมูล Supabase จริงไม่ได้ เพราะยังไม่มี URL/key ของโปรเจกต์เจ้าของบัญชี โปรดอย่าโพสต์ `service_role` key หรือรหัสผ่านในแชต

## ตารางเรียนส่วนกลางและตารางส่วนตัว

ระบบรองรับห้อง `1/1, 1/2, 2/1, 2/2, 2/3, 2/4, 3/1, 3/2, 3/3, 4/1, 4/2, 4/3, 5/1, 5/2, 6/1, 6/2` เลือกภาคเรียน/ปีการศึกษาได้ โดยเริ่มที่ภาคเรียน 2 ปีการศึกษา 2569 และแสดงตัวเลือกสายวิทย์-คณิต/สายทั่วไปเฉพาะ ม.4–ม.6 ตารางส่วนกลางและส่วนตัวแยกตามห้อง ภาคเรียน ปีการศึกษา และสายเรียน

- แอดมินเลือกห้อง/ปี/ภาคเรียน กดแก้ไขแล้วคลิกช่องคาบเพื่อเปิดหน้าต่างกรอกชื่อวิชาและข้อมูลเสริม ระบบยังไม่กำหนดรายวิชาให้ เพราะโรงเรียนยังไม่ประกาศวิชาในช่วงปิดภาคเรียน จากนั้นกด **เผยแพร่ตารางส่วนกลาง**
- นักเรียนกด **ซิงค์ตาราง** เพื่อโหลดตารางกลางล่าสุด หรือแก้ไขและกด **บันทึกตารางของฉัน** เพื่อสร้างตารางส่วนตัวซึ่งมีเพียงบัญชีนั้นอ่าน/แก้ไขได้
- ต้องรัน `supabase-schema.sql` ก่อนเปิดใช้งาน ตารางจะยังว่างจนกว่าแอดมินจะเผยแพร่ข้อมูลจริง
- หลังสมัครบัญชีแอดมินครั้งแรก ให้เพิ่มสิทธิ์จาก Supabase SQL Editor โดยแทนอีเมลตัวอย่างด้วยอีเมลแอดมิน:

```sql
insert into public.schedule_admins (user_id)
select id from auth.users where email = 'admin@example.com'
on conflict (user_id) do nothing;
```

ห้ามให้สิทธิ์แอดมินกับบัญชีที่ไม่ควรเผยแพร่ตาราง ระบบตรวจสิทธิ์นี้จากฐานข้อมูลและ RLS ไม่ใช่จากการซ่อนปุ่มในหน้าเว็บ

## เผยแพร่ด้วย GitHub Pages

อัปโหลดไฟล์โปรเจกต์ไปยัง GitHub repository แล้วเปิด Settings > Pages เลือก branch และโฟลเดอร์ที่เก็บ `index.html` ให้เรียบร้อย หลังได้ URL เช่น `https://ชื่อผู้ใช้.github.io/ชื่อ-repo/` ให้ใส่ URL นั้นเป็น Site URL และ Redirect URL ที่อนุญาตใน Supabase Authentication > URL Configuration เพื่อให้ลิงก์ยืนยันอีเมลกลับมาที่เว็บไซต์ได้
